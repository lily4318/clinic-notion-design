# 研究進度、舊模組稽核與變更核可清單

## 研究目標與目前證據

使用者要求至少10,000篇 Notion 官方文件／模板／UX／資料庫設計學習。這是**尚未完成的研究目標**，不是已讀成果。首批已建立 16筆唯一來源登錄、14筆取得正文並核對與專案相關段落、2筆僅有搜尋摘錄；**可證明符合逐篇深入精讀標準：0**。不把搜尋結果量、不同語系同文或模板目錄當成閱讀成果。

後續每一筆新增來源需記：ID、canonical URL、標題、作者／網站、發表／最近查核日期、類別、來源內容位置／版本、閱讀層級、設計摘要、反例／風險、採用狀態與已關聯的 GitHub 決策。先去重再計數。

## 舊模組下一階段的「一次完整檢查」產物

先**唯讀**對 10 個原有功能頁面核對：頁面實際嵌入的 unique data source 數、View ID／名稱、固定篩選、排序、可見屬性、使用者日常操作任務、狀態欄位來源、Formula／Rollup 深度與角色權限依賴。既有盤點 76 個嵌入／引用區塊非 unique databases，不得將「區塊多」直接當成要刪除的理由。

優先：Billing（14引用）、Events/Groups（15）、Staff（14）；之後 Cases/Episodes、Sessions，再處理 Intake/Rooms/Tasks/Projects/Documents。只根據實際痛點提出 A 不變、B 最小調整、C 大幅重構分類。

## 大幅修改前必填比較

| 檢查面向 | 必要內容 |
|---|---|
| 現況基準 | 最新 00.config_notion／Schema／Relation／View、頁面時間與備份 |
| 問題來源 | 已觀察到的操作失誤／重複輸入／資料不一致，非只因模板好看 |
| 替代方案 | A不改、B UI最小修、C Schema/流程重構及保守方案 |
| 資料影響 | 哪些源資料、欄位、Relation、Formula、View、Role、歷史核定期 |
| 效能 | 原/新首頁同時負載、欄位/公式依賴、測量方式 |
| 安全 | Free 方案權限邊界、TEST/啟用關聯隔離、個資遮罩 |
| 測試 | 同年兩政府方案、同方案跨年、兩個核定期別、不同計數、逾期、取消、他處未知/0/不適用、重複參與 |
| 回復 | 原生頁面／資料庫備份、變更 ID 清單、write-after-fetch 與驗收回復 |
| 核准 | 重大調整使用者**明確同意**後才能修改 |

## 本輪交付界線

此研究知識庫只增補 GitHub 文件，不修改任何 Notion TEST 頁面／View／業務資料，不上傳外部素材或敏感個資。待完整研究與評估證據具備後，才能把建議列成「已經研究」；實作須另完成 TEST 驗收。原已完成的 vNext 首頁，不自動視為所有其他行政模組的重構授權。



## 2026-10-24｜十個既有行政模組完整唯讀稽核｜實際進度

**第一階段唯讀配置稽核完成**：逐個讀取原有十頁、76個嵌入區塊及其177個 View 設定，核對23個去重 Data Source Schema（636欄、152 Formula、147 Relation、48 Rollup）。已整理完整的模組前後比較、7類風險與「B1 精確性／B2 導覽／B3 一致性／C 暫停」整批實作方案，詳見 [十模組稽核報告](../audits/ten-module-structure-ux-audit-2026-10-24.md)。這一階段**沒有任何 Notion 編輯**。

尚待：00.config_notion 映射完整查核、各角色實際 GUI、真實延遲、代表性資料狀態分支與來源 Formula 值及10,000篇外部研究。B 級整批實作前仍要取得目前使用者要求的核准與獨立 TEST 驗收證據，不擅自套用現有臨床／財務資料。
