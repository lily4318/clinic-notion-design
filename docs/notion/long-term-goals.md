# Notion 長期目標 v2｜2026-10-24 修訂

**定位**：這份文件定義 Notion TEST 工作台、資料模型與設計研究的**可驗收成果目標**。不取代《治療所行政前台網站需求規格書》，也不直接授權修改正式 GAS、Cloud Run、中央 Session 或尚未核准的共享 Schema／Formula／Relation。

## 北極星目標

讓治療所行政人員能在**權限許可、資料不混算、操作直覺、效能可量測、每次修改可驗證與回復**的前提下，按實際工作任務完成服務、帳務、補助與營運管理。

以前以「先閱讀大量模板／10,000篇，再全面重新設計」作為單一進度想像，缺少可驗證完成定義。從本版起改為**研究證據 → 風險假設 → TEST → 使用者驗收 → 受控實作 → GitHub 追溯**；研究篇數不作安全或易用性的代理指標，也不阻擋可在隔離環境驗證的改善。

## 原「1,000／10,000 篇」要求的修正與衝突處理

歷史對話曾要求至少**1,000 篇 Notion 模板設計**；後續 GitHub 文字出現**10,000 篇 Notion／資料庫／UX 研究**。兩者範圍不同，且未經足夠可核實的逐篇精讀清冊，不應擅自換算或宣稱完成。本文件將此列為**原有未結案研究需求／數字口徑待確認**，不自行將1,000改成10,000或反之；任何閱讀目標仍須留下 URL、去重、來源片段、設計適用性和完整閱讀級別。**不將任意篇數視為 Notion UX 上線或資訊安全的驗收門檻。**

已保存的研究基準是 **16 筆去重來源，14筆曾取得正文並核對相關段落、2筆搜尋摘要、0筆可證實逐篇深入精讀、0套外部模板逐套實測**（見 [原始證據清冊](research/evidence-register-2026-10-24.md)）。這是歷史取證狀態，並非本回合額外完成16篇。

## 執行順序及界線

1. **已完成本輪**：盤點先前研究文件、將來源對應決策與目前 TEST 實作，重整 [TEST 行政任務工作台 v2](https://app.notion.com/p/4038ca66aa4d814297a2dbe27e8d054d)；原十個行政模組及其資料來源不重構。
2. **下一個可驗收階段**：同一份完整任務情境清單測試行政入口與新版 View，檢視頁面實際可讀性／載入速度、確認是否真正改善，不再持續新增零散區塊。
3. **通用政府補助**：等官方該期規則、最新 `00.config_notion`、Data Source Schema／View／Relation、真實 Sessions 狀態和隔離 TEST 可核實，再提出共享 Formula／業務寫入計畫。重大調整需取得使用者明確同意。
4. **其他十模組**：只有已證明誤導或錯誤的 B 類修正才能批次調整；C 類核心 Schema／關聯／授權變更維持未核准，並保留可回復的方案。
5. **研究迭代**：以尚未解決的工作痛點決定查閱哪些官方文件、代表性模板及 UX 證據，再將可驗證結論回填研究索引與 decision log。不能把蒐集量當作研究品質。
