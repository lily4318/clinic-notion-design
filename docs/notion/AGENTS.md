## 使用者否決後的清理原則（2026-10-24確認）

「不適合／不要／刪掉」代表**從Notion實際使用的頁面、資料庫與操作流程移除**，而非只把舊元件收合、隱藏、停用或無限期保存舊TEST頁／重複View。需清除遭否決元件本身及確定無其他用途的專屬Formula／Rollup／Relation／View／欄位／按鈕／頁面，並回查顯示和操作路徑是否真的消失。

執行順序：讀最新Schema、頁面、Saved Views、完整Formula及按鈕動作→證實引用鏈與其他功能→建立與使用畫面分開的短期回復備份→先安全移除引用或轉接保留功能→真正刪除→查驗資料與介面、跨期補助及回復。必要法定病歷／財務紀錄、仍供其他業務使用的來源、並行修改不能誤刪。若缺少完整原文、必要備份或無法回復，**明確標記待安全刪除（BLOCKED）**，不以隱藏冒稱完成；一旦解除阻擋即可接續清理，不要求使用者再次核准相同刪除意向。TEST標籤不構成資料隔離。已廢止的預覽與回復備份不得長期佔據日常工作台。


## Notion日常介面與AI內部規則分離（2026-10-25使用者確認）

- **Notion日常工作頁只顯示操作所需資訊**：清楚的功能名稱、真正需要判斷的數據／狀態／警示、簡短操作提示、必要的異常處理入口。優先讓人員直接看見並操作資料，避免大篇幅文字佔據首屏。
- **禁止將AI設計規則或內部工作指令寫入Notion業務頁**：含資料模型原則、架構限制、實作決策理由、AI驗收規範、測試結果與稽核過程、如何跨方案擴充、未啟用功能聲明、回復／備份方式，以及「不需另外建立某清單／不得把某規則套用到其他方案」等給設計者而非現場使用者看的排除條件。這些應保存在GitHub之AGENTS、decision-log、architecture／UX／audit／acceptance-status，必要時寫Google Docs規格，不複製貼到Notion頁面。
- **本次使用者明確否決的例子**：在「補助方案管理｜TEST」頁面以大量文字說明「青壯人工確認資格→服務歷程選方案→查看額度」、不必建立資格清單／年度參與紀錄、單一歷程與跨方案規則差異，並用①②多節標題長篇解釋。這些應作為GitHub內部設計規格；若工作者確有必要在Notion看到該資訊，僅保留短而明確的操作標籤、必要警示或一行提示，不照搬設計原文。
- **內容例外與安全界線**：若使用者明確要求在Notion放置特定說明，或為實際執行、法令／告知／安全／資格判斷不可缺少，可保留最小必要、以使用者能理解的工作語言撰寫；不得因此刪除原始Data Source、歷史／法定紀錄、必要警示或影響其他模組的功能。**內部紀錄和Notion作業資訊分離，不是把必要資訊單純隱藏。**
- **動手前後檢查**：寫入或重設Notion頁面前逐段判斷「使用者在此頁此刻需要看／做什麼？」；屬AI或維護者規則就記GitHub，不放在Notion；完成後核對工作台是否精簡、原有必要資料與操作入口及權限仍可用。若需移除既有文字，必須先重新Fetch實際頁面、核實附屬內容與並行更新，精準移除並回查；**單純增加此GitHub規則不授權立即修改Notion**。


適用於本儲存庫的 Notion 資料庫、政府補助、工作台與 TEST 驗收。

2. 再讀 Notion TEST 當前 Database / Data Source Schema、Relation 目標、Formula / Rollup、View 與必要原始資料；同步核對目前使用中的 Google Docs 規格。GitHub 是決策索引，不是即時資料鏡像。
3. 確定當前 TEST / 純設計範圍、上次驗收進度、尚未通過項目和其他人並行改動。不得要求使用者再貼已可取得的規格或程式。
4. 任何寫入前查實際 Relation；標記 [TEST] 不代表真正隔離。有三筆歷史隔離 Session 曾連到啟用中的 115 方案，不能拿來直接做改狀態測試。

## 核心不變條件

- **多政府方案 × 多年度／核定期別 × 每期獨立規則。** 青壯、115、每案三次、每週六次、七天間隔、三個月期限等只可屬於已確認的特定核定期，不可寫死在共用模型、通用公式或 View。
- 核定期不必是自然年度。以 Price Plan 方案實例 ID 作歸屬，參與紀錄的候選唯一鍵為「個案 ID + Price Plan ID」；不同政府方案或期別不得混算，除非有已核實的跨方案共用額度規則。
- Cases 永久個案主檔；Care Episodes 管真實臨床歷程；Sessions 依實際 Price Plan Relation / 狀態計算候選占用；Staff 與方案關聯的週紀錄依當期規則判斷；Price Plans 依核定期別設定上限及期間。既有關聯優先保留，避免每年複製資料庫。
- 未確認、未知、不適用、已確認零，嚴格區分；未核實不作放行判斷。會談與歷程收費方案不一致列異常，禁止擅自改歷程。逾期但歷程進行中保留顯示並提醒，不自動隱藏／結案。
- Notion 免費版優先，View 隱藏不代表資料權限。避免無必要的 Relation / Rollup / Formula / 快照欄位 / 自動化。

## 修改分級

A 保留：沒有實證問題，不改。
B 最小修正：名稱、排列、顯示欄位、提示、收合等；先查依賴、備份和 TEST 驗證。
C 重大修正：新增／拆分核心資料庫、更改 Relation、共享 Rollup / Formula、批次關聯既有資料或全面改動 UX；先交付前後比較、效益、風險、影響及回復／驗收計畫，**取得使用者明確同意才改**。其他舊模組原則上只有 A / B。

## TEST 與安全

- 寫前重新 Fetch 最新 Schema 與目標頁面及 Relation，確認權限、型別、選項和範圍；採最小必要寫入，不覆蓋非本次修改。
- 優先使用真正隔離的 TEST 資源；涉及既有臨床紀錄或啟用方案時先唯讀。
- 寫後 Fetch 驗證資料、計算與 View，必要時復原。無法取得 Notion 原生 Formula 值時，不可用算術推論標記 PASS。
- 禁止向 GitHub 輸出個資、病歷、財務細項、秘密、原始資料列或敏感設定。
- 本階段 **不處理正式 GAS、Cloud Run、中央 Session 或部署**，除非使用者另明確要求。
